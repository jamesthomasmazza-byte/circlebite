# Open Food Facts tags the matcher couldn't read: real-product evidence (2026-11-03)

Tags match keywords by exact equality, after `openFoodFacts.ts` strips the language prefix,
lowercases, and turns hyphens into spaces. Three of Open Food Facts' own allergen tags equalled no
keyword:

| OFF tag | Normalized | Keyword before |
|---|---|---|
| `en:sesame-seeds` | `sesame seeds` | only `sesame`, `tahini` |
| `en:sulphur-dioxide-and-sulphites` | `sulphur dioxide and sulphites` | sulphite, bisulfite… `sulphur dioxide` |
| `en:molluscs` | `molluscs` | species only: oyster, mussel… |

So a product tagged only that way read as clear for that allergen. The fix adds the three spellings
as keywords (`mollusc` as well as `molluscs`). They are keywords only, never aliases, so no
correction key moves; this is the same call as `nuts`. Approved by JT after review, 2026-11-03.

**Mustard is not a gap.** It has no cluster, but a "Mustard" profile falls back to the literal
word, which equals the normalized tag. All 133 mustard-tagged products in the sample already matched.

## Method

- **Sample:** the same 1,810 Open Food Facts products as `2026-11-03-underscore-allergens.md`.
- **Matcher:** the repo's own `computeVerdict`, with the underscore fix (`cf05bf9`), on tags and
  text together.
- **Profiles:** a parent's allergen named Sesame, Sulphites or Molluscs. Traces are not treated as
  unsafe (the default), so a traces tag reads **May contain**.
- **Compared:** before and after the three keywords were added.

## Result

These products read **No listed allergens found** for that allergen before the fix:

| Profile | Now **Contains** | Now **May contain** |
|---|---|---|
| Sesame | 16 | 97 |
| Sulphites | 4 | 4 |
| Molluscs | 4 | 6 |
| **Total** | **24** | **107** |

The 131 total counts product–allergen pairs: it is **121 distinct products**, some warning for two
allergens. *(Corrected 2026-11-03: this line first called 131 "about seven times the underscore
gap", which was both the wrong unit and the wrong ratio.)* Another 67 already read **Contains**,
from the text; the tag now matches first, so only the source changes. No product lost a match. Full list:
`2026-11-03-tag-gap.tsv`.

**Where the new warnings come from:** 130 of the 131 come from the product's own Open Food Facts
tag. One comes from text: Soba noodle spicy (`5997523315535`), `…crustaceans, fish, milk, molluscs,
mustard and sesame`. That is a "may contain" line, and it reads **Contains**, because the matcher
doesn't recognize "may contain" inside ingredient text. That is an existing limitation, as in the
underscore evidence; principle 1 accepts it.

## Known false caution: a wrong tag we trust

Nutritional Yeast Flakes (`5016084000374`) is tagged `en:sulphur-dioxide-and-sulphites`, and now
reads **Contains** for a Sulphites profile. Its text names "Zinc sulfate", and sulfate is not
sulphite, so the tag is probably Open Food Facts' mistake. Accepted: the matcher trusts every tag
the same way, and principle 1 prefers a false caution to a false safety. A test pins this case
(`match.test.ts`), so the warning is known to be the tag's alone.

## Still not read

Words Open Food Facts kept as tags without mapping them (`en:lait`, `en:Milch`, `en:Weizenmehl`,
`en:blé`, `en:magermilchpulver`, under various language prefixes) still equal no keyword. Each
appeared on 3–7 products in the sample, and every one of those products also carries the mapped
English tag (`en:milk` or `en:gluten`), so none is a miss. Not part of this fix.
